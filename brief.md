# Musubix - Project Specifications & AI Coding Guidelines

## 1. Project Overview
**Name:** Musubix
**Tagline:** Borderless Micro-Freelance Platform Powered by Stellar.
**Description:** A Web3 freelance marketplace designed for micro-tasks and local economies. It solves the cash flow and trust issues in the gig economy using Soroban Smart Contracts for automatic, low-fee escrow, and Stellar Path Payments for seamless cross-border transactions (USD to IDR). 
**Target Audience:** Micro-freelancers (students, entry-level professionals) and local SMEs/international clients.
**Hackathon Constraint:** This is an MVP for the APAC Stellar Hackathon. Focus on core escrow flow, path payments, and a clean, bug-free user experience over feature bloat.

## 2. Tech Stack
*   **Frontend:** Next.js (App Router), React, Tailwind CSS, TypeScript.
*   **Backend:** NestJS (Microservices Architecture), TypeScript, Prisma ORM.
*   **Blockchain/Web3:** Stellar SDK, Soroban Smart Contracts (Rust).
*   **Database:** PostgreSQL (Relational data: users, job listings, metadata).

## 3. Core Features (MVP Scope)
Strictly implement the following features. Do not add complex chat systems or forums.
1.  **Auth & Wallet Abstraction:** 
    *   Users log in via email/password or Google OAuth.
    *   Backend automatically provisions a Stellar keypair for new users (custodial wallet for MVP to ensure smooth Web2-like UX).
2.  **Job Marketplace:**
    *   Clients can post a job (Title, Description, Budget, Currency).
    *   Freelancers can view and accept jobs.
3.  **Smart Escrow System (The Core):**
    *   Client funds the escrow.
    *   System locks funds in a Soroban smart contract.
    *   Freelancer submits work (URL/Text).
    *   Client approves work -> Smart contract automatically releases funds to the freelancer.
4.  **Cross-Border Path Payment (The Magic):**
    *   If a Client pays in USD (USDC on Stellar) and the Freelancer wants IDR (IDR stablecoin), the smart contract/backend uses Stellar Path Payments to auto-convert at the best DEX rate during the payout.
5.  **Fee System:**
    *   Flat 5% platform fee deducted automatically during the smart contract payout. No yield generation (Sharia-compliant).

## 4. Design System & UI/UX Guidelines
**Design Philosophy:** Abstract the blockchain. Users should not see words like "Gas Fees," "Mainnet," or "Transaction Hash" in the main UI. It should look like a modern Web2 SaaS.

**Color Palette:**
*   **Primary Brand:** `#0F172A` (Slate 900) - For navbars, primary text, dark mode backgrounds.
*   **Primary Action:** `#3B82F6` (Blue 500) - For main buttons, links, active states. Represents trust and finance.
*   **Accent/Success:** `#10B981` (Emerald 500) - For "Funds Locked", "Payment Released", and success toasts.
*   **Warning/Alert:** `#F59E0B` (Amber 500) - For pending actions, dispute warnings.
*   **Background (Light):** `#F8FAFC` (Slate 50) - App background.
*   **Card/Surface:** `#FFFFFF` (White) - For job cards, modals.

**Typography:**
*   **Font Family:** Inter or Poppins (via `next/font/google`).
*   Clean hierarchy: `h1` for page titles, `h2` for section headers, `p` for descriptions.

**Component Standards (Tailwind):**
*   Cards: `bg-white rounded-xl shadow-sm border border-slate-100 p-6`
*   Buttons (Primary): `bg-blue-500 hover:bg-blue-600 text-white font-medium rounded-lg px-4 py-2 transition-colors`
*   Status Badges: Small, rounded pills (e.g., `bg-emerald-100 text-emerald-700 text-xs px-2 py-1 rounded-full`)

## 5. System Architecture (Next.js + NestJS Microservices)

### Frontend (Next.js)
*   **Role:** UI rendering, client-side state management, calling Backend API Gateway.
*   **Structure:** 
    *   `/app/client/dashboard` (Client view)
    *   `/app/freelancer/dashboard` (Freelancer view)
    *   `/components/ui` (Reusable UI elements)

### Backend (NestJS Microservices)
*   **API Gateway Service:** Handles HTTP requests from Next.js, authenticates users, and routes payloads to specific microservices via TCP/Redis.
*   **User & Job Service:** Manages PostgreSQL CRUD operations for user profiles, job postings, and job statuses (`OPEN`, `IN_PROGRESS`, `IN_REVIEW`, `COMPLETED`).
*   **Stellar Integration Service:** 
    *   Communicates directly with Stellar Horizon/RPC.
    *   Handles transaction building, signing, and Soroban contract invocations.
    *   Manages the platform's treasury (the 5% fee collection).

7. AI Coding Agent Directives (CRITICAL)

When writing code for this project, the AI must strictly adhere to the following rules:

    Promising Beginner Pragmatism: Write clean, readable, and highly maintainable code. Do NOT over-engineer with enterprise patterns that are unnecessary for a hackathon MVP. Prove architectural competence through logical separation of concerns (Frontend -> API Gateway -> Microservices), not through convoluted abstractions.

    Modular & Component-Driven: Keep Next.js components small. Separate business logic from UI.

    Error Handling: In the NestJS and Stellar integration services, implement robust error handling (Try/Catch). If a blockchain transaction fails, the database state must NOT update to "LOCKED" or "COMPLETED".

    Fault-Oriented Testing Focus: When generating critical functions (like releaseEscrow or pathPayment), always include comments explaining edge cases (e.g., "What if the DEX liquidity is too low for the path payment?").

    Strict Typing: Use TypeScript interfaces and types for all payloads. No any types.

    Vibe/Tone: Keep comments informative and directly related to the logic.
